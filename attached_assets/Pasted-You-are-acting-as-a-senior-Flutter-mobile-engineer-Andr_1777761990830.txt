You are acting as a senior Flutter mobile engineer, Android release engineer, product owner, QA lead, and Google Play launch assistant.

Project context:
We are building an offline-first Ethiopian exam grading app called EthioGrade / GradeFlow Ethiopia.

The app’s purpose:
Help Ethiopian teachers reduce manual grading time by scanning objective answer sheets, detecting answers offline, allowing teacher review/correction, calculating scores, and exporting results. The app must work on low-end Android phones, preferably offline, with a small app size and high teacher trust.

Core user:
A teacher in Ethiopia who grades multiple classes and wants to save time. The teacher may have unstable internet and a low-end Android phone.

Known validated pain:
Teachers can spend around 1.5–2 hours grading 10 questions for 40 students manually. The MVP must reduce this burden for objective exams.

Existing product direction:
Do NOT build a magical full AI grader first. Build a reliable OMR-first grading tool.
OCR and essay grading are future phases, not the first Play Store release unless already safely implemented.

Main MVP features:
1. Quick Assessment mode
   - Teacher can grade without creating a full class/student database.
   - Teacher enters answer key manually.
   - Teacher optionally enters expected paper count.
   - Teacher scans papers.
   - App calculates result.
   - Teacher can export or save results.

2. OMR grading
   - Support one fixed template first: “GradeFlow Bubble 20 v1”.
   - Detect answers offline.
   - Classify each question as:
     - SINGLE
     - BLANK
     - MULTIPLE
     - LOW_CONFIDENCE
   - Generate reason-coded issues:
     - TEMPLATE_UNSUPPORTED_QUESTION_COUNT
     - TEMPLATE_ALIGNMENT_LOW
     - LOW_OVERALL_CONFIDENCE
     - QUESTION_REVIEW_REQUIRED
   - Never silently trust uncertain detection.

3. Teacher review screen
   - Show captured image.
   - Show detected answers.
   - Show score.
   - Show confidence/issues.
   - Allow teacher correction.
   - Allow retake.
   - Allow manual fallback.
   - Confirm final result only after teacher review.

4. Results
   - Show per-paper score.
   - Allow recalculation if answer key changes.
   - Export CSV.
   - Keep Quick Assessment result lightweight.
   - Avoid requiring student registration for the first release.

5. Offline-first
   - Core grading must work without internet.
   - Do not depend on cloud APIs for grading.
   - Store local data safely.
   - Avoid unnecessary login for MVP.

6. Low-end Android constraints
   - Optimize for 2GB RAM Android devices.
   - Avoid heavy OCR/ML dependencies unless absolutely necessary.
   - Keep APK/AAB size controlled.
   - Avoid large bundled models.
   - Use bounded image decoding and memory-safe processing.

7. Play Store readiness
   - Prepare Android release build as AAB.
   - Target current Google Play requirement: targetSdkVersion 35 or higher unless project tooling supports newer safely.
   - Use minSdk appropriate for low-end Android support, preferably minSdk 26 unless current project requires otherwise.
   - Configure app name, package id, launcher icon placeholder, versionCode, versionName.
   - Prepare release signing instructions but do NOT expose secrets.
   - Produce Play Store listing draft.
   - Produce privacy policy draft based on actual data collected.
   - Produce Data Safety form notes based on actual permissions and storage.
   - Prepare screenshots checklist.
   - Prepare closed/internal testing checklist.
   - Do not claim the app is medically, officially government, or school-authority certified.
   - Do not claim 100% grading accuracy.
